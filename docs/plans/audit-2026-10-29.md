## P0. Прод и данные (сначала)

1. **Баг «Новое от ИИ» (Фаза 13b).** Сегодня не воспроизводится: лимит LLM исчерпан, проверять после 00:00 МСК. Самая вероятная причина: ответ Groq обрезается по `max_tokens`.
   - Промпт просит 15 игр с `reason` до 200 символов по-русски, а `LLM_MAX_OUTPUT_TOKENS = 2000` общий с «Из бэклога» (`src/server/recommend/phrase.ts`). Кириллица у llama ≈ 2–3 символа на токен: 15 × (название + 200 символов + JSON) ≈ 1500–2500 токенов.
   - Обрезанный JSON даёт `bad_response`, а в режиме `json_object` Groq может отвечать `400 json_validate_failed`. `llmReason=unknown` — строка неудачи, записанная до диагностики (без поля `reason`).
   - Правка: отдельный лимит для discover (4000), `reason` до 120 символов, 12 игр вместо 15; писать в лог `finish_reason`; при `length` — `llmReason=truncated`. Проверка: `/api/recommend/discover?refresh=1` на проде.
2. **LLM-лимит.** Раздельные счётчики для «Из бэклога» и «Новое от ИИ», неудачный вызов не тратит лимит (или тратит, но не больше 3 в сутки). Иначе один день отладки 13b оставляет без фраз оба режима.
3. **Тихий отказ cron не алертится.** Telegram `sync_stale` срабатывает только из `notifyAfterSync`, то есть когда синк запустился и упал. Если cron не вызывается вовсе, предупреждения нет.
   - Правка: проверка «последний успех старше 36 ч» при любом открытии сайта (SyncBanner уже есть) + отдельный лёгкий cron-пинг или проверка в `/api/health`, которая шлёт Telegram. Без платных сервисов.
4. **Нет резервной копии ручной разметки.** Статусы и даты `completed_at`/`dropped_at` невосстановимы (`api-contract.md` §6.7). История Neon на бесплатном плане короткая.
   - Правка: раз в неделю cron отправляет в Telegram JSON-выгрузку `game_status` + `planned_games` + `roadmap_order` (документом). Кнопка «Скачать копию» в меню профиля.
