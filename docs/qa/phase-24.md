## 1. Backend: проверено
- Порядок 401 -> 403 -> Origin/Content-Type 400 -> config 500 -> формат 400 -> лимит 429 -> PSN: соответствует контракту 27.1. Member 403 и аноним 401 не доходят до PSN.
- Формат: 64 символа `[A-Za-z0-9]`. Отклонены (400, PSN не вызван, лимит не расходуется): пустое, пробелы, null, массив, объект, число, полноширинные символы, кириллица, нулевая ширина, эмодзи, NUL, перевод строки, `%41...`, 128 символов, битый и вложенный JSON, ключ `NPSSO` другого регистра. Принято: чистое значение, кавычки, `{"npsso":"..."}` (в т.ч. с лишними полями).
- Тело 2 МБ: 400, PSN не вызван.
- Лимит: 3 неудачи/15 мин на IP, 4-я 429 с `Retry-After`; 10/час глобально (с 4 IP, 11-я с нового IP заблокирована); успехи лимит не едят; временный сбой PSN (503) считается неудачей. 6 параллельных неудач: до PSN доходят ровно 3 (advisory lock работает). Новая CHECK не ломает `password` и `google` (вставки проходят, счётчики независимы).
- Гонка двух вставок: одна целая запись `psn_auth`, два события `pasted`.
- Секреты: NPSSO и токены не найдены ни в ответах всех исходов (200/422/503/исключение с NPSSO в тексте), ни в `console.*`, ни в `psn_auth`, `psn_token_events`, `login_attempts`, `sync_runs`. Токены в `psn_auth` зашифрованы. При отказе PSN прежние токены не стираются (проверено сравнением строки).
- Журнал: максимум 200 событий, `expired` не дублируется. `/api/sync/status`: `psnToken`, `psnAuth` становится `ok` после принятого NPSSO.

## Баги и замечания
**QA-24-1 (Низкая). Нет ограничения размера тела до разбора.** `route.ts` делает `await req.json()` до проверки формата; ограничивает только лимит платформы Vercel (4,5 МБ). Ошибка формата не расходует лимит попыток. Риск минимален: эндпоинт только для owner за сессией и Origin. Правка: читать `req.text()` и отвергать тело длиннее ~1 КБ. Шаги: POST `{npsso:"A"x2000000}` -> 400, но тело целиком разобрано (тест это подтверждает только по результату).

**QA-24-2 (Низкая). Нет теста реальной роли owner на уровне БД.** Тесты route подменяют `requireOwner` (`test-require-user`); сама проверка `requireOwner` (роль из БД) в этой фазе новых тестов не получила, по коду корректна (`r.user.role !== 'owner'` -> 403). Рекомендация: один интеграционный тест на настоящий `requireOwner` с member-сессией.

**QA-24-3 (Информационно). Срок жизни NPSSO и реальные ответы PSN не проверены.** Мок-PSN не заменяет прогон на проде: после выкладки владельцу стоит один раз вставить NPSSO и убедиться, что в панели появились «Токен обновлён», «Источник: с сайта».
