- Смена: завеса «Открываю профиль …» видна, `data-psw` и `visibility: hidden` на контенте; после неё в `main` только игры нового профиля (прежних нет); тост «Профиль PSN: …».
- Добавление: все коды `invalid_request`, `profile_limit`, `user_limit`, `psn_id_taken`, `psn_not_found`, `psn_private`, `rate_limited` (таймер в кнопке, `Добавить (N)`), `psn_unavailable` («Повторить»), сеть, неизвестная 500; форма остаётся открытой; формат ника блокирует кнопку.
- Лимит 3 из 3: «Добавить» отключена, причина текстом; пустое состояние при одном профиле.
- Отвязка: кнопка включается только при точном нике (регистр и пробелы игнорируются), архив с «удалится через 30 дней», «Вернуть» (3 из 3 снова), «Удалить сразу» с подтверждением, ошибки `confirm_mismatch`, `sync_in_progress`, `not_found`, отвязка активного профиля -> открывается основной.

- Безопасность (живой dev-сервер + PGlite): без cookie 401 на всех роутах профилей и редирект `/profiles` на `/login`; cookie с изменённым `pid` без пересчёта подписи, подпись чужим секретом, `pid` = 0, -5, 1.5, "2" -> 401; валидно подписанный `pid` при недоступной БД не даёт 200; `pid` в query не влияет; IDOR, чужой/архивный профиль -> одинаковый 404, лимиты и гонки, смена профиля не продлевает срок — тесты `routes.test.ts`, `session-profiles.test.ts`, `profile-isolation.test.ts` зелёные. В новом коде нет `console.*`, токены и NPSSO в ответах профилей не отдаются.

## Ночная цепочка синка: замер

Стенд: PGlite, движок PSN заменён заглушкой, 6 профилей (2 входа по 3). Результат: 6 запусков `daily`, у каждого свой `sync_runs`, порядок по `id`, цепочка `?queue=<id>` дошла до конца сама; накладные расходы оркестрации около 85 мс на всё (14 мс на профиль), то есть пренебрежимы.
Реальное время определяет PSN, живьём не измерялось. Оценка по контракту (8.4 и 41.4): обычный день один профиль = одно звено до `SYNC_TIME_BUDGET_MS` (50 с, обычно 20-40 с) -> 6 профилей около 3-5 минут; первый синк нового профиля около 3 звеньев (2-2,5 минуты) плюс 1-2 суток на цвета обложек. Лимит функции Vercel (60 с) от числа профилей не зависит: каждое звено — отдельный вызов. Вывод: ночное окно не проблема (укладывается в 10 минут при 6 профилях); растёт число обращений к PSN под одним NPSSO, параллели нет. Риск: обход держится на цепочке самовызовов, сбой одного вызова (сеть, холодный старт) обрывает хвост очереди до завтра; watchdog `sync_missed` это увидит.
