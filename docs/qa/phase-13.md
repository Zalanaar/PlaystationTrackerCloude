## Баги и замечания

### N-1. Скрытые игры не вернуть после перезагрузки (средняя/низкая, backend + frontend, открытый вопрос спеки 13.1)
Шаги: нажать «Не интересно», обновить страницу. Игра исчезла, API не отдаёт список `recommend_dislikes`, снять отметку можно только тостом «Отменить» или «Вернуть скрытые» в рамках сессии. Единственный путь после перезагрузки: SQL. Если все игры бэклога скрыты, экран предлагает «новые появятся здесь сразу», но вернуть скрытые нельзя. Предложение: `GET /api/recommend/dislikes` и блок «Скрытые» (или авто-снятие дизлайка при смене статуса игры на любой иной и возврате в backlog).

### N-2. Проверка ссылок в фразе LLM по списку TLD (низкая, backend)
Шаги: `isValidPhrase('bit.ly/abc')`, `goo.gl/x`, `evil.co/a`, `evil.to`, `evil.cc` возвращают true (в `LINK_RE` TLD из короткого списка). UI показывает текст как обычный React-текст (не ссылка, XSS нет), риск косметический (в рекомендации может оказаться «кликабельный по смыслу» адрес для копирования). Предложение: отбрасывать любой токен вида `\w+\.\w{2,}\/` и вообще любые точки между буквами без пробела.

### N-3. Проверка «чужое название» слабая (низкая, backend)
Сравнивается только с названиями из той же пачки (до 3 игр) и только при длине названия >= 3; короткие названия («Ico» проходит, «Fez», «It») и игры вне пачки не ловятся. Модель получает только факты, поэтому названия вне пачки она может взять лишь из собственных знаний. Принять или добавить в стоп-лист названия всей библиотеки.

### N-4. Нет схлопывания одинаковых запросов (низкая, backend)
Два одновременных GET с пустым кэшем (две вкладки) оба тратят вызов LLM. Ограничено лимитом, поэтому лишь расход бесплатной квоты. Принять.

### N-5. Вызов LLM, закончившийся ошибкой, расходует лимит (информационно)
Так задумано в 18.8; при нестабильном провайдере 20 вызовов/сутки могут уйти на неудачи, дальше `limit` (шаблоны). Принять.

### N-6. Дизлайк вечный (низкая, продукт)
Игра, скрытая из подсказок, не возвращается даже после выхода и повторного попадания в бэклог. Связано с N-1.

## Баги

### BUG-D1. Параллельные `?refresh=1` обходят лимит 3 в сутки (средняя/низкая, backend)
Шаги: при `refreshes=2` отправить 6 параллельных `GET /api/recommend/discover?refresh=1` (две вкладки, двойной запрос, скрипт). Все читают `refreshes=2`, все проходят проверку `refreshLeft`, все зовут Groq (6 вызовов вместо ≤1), каждый пишет `refreshes + 1` (в БД 8, `refreshLeft` в ответах противоречит друг другу). Ограничено только `LLM_DAILY_LIMIT`. Причина: проверка и увеличение счётчика `refreshes` не атомарны (`getDiscover`: `readCache` ... `writeCache`). Предложение: резервировать refresh атомарным `UPDATE ... SET refreshes = refreshes + 1 WHERE day = $1 AND refreshes < 3 RETURNING` до вызова Groq. Тест: `it.fails` «BUG-D1» в `qa-phase13b-discover.test.ts` (после исправления снять `.fails`).

### BUG-D2. ™ ломает сверку с библиотекой и каталогом (средняя, backend)
Шаги: в библиотеке «Control™» (PSN отдаёт ™/® в названиях), модель предлагает «Control», RAWG возвращает «Control». `normalizeTitle('Control™')` = `controltm`: `normalize('NFKD')` раскладывает ™ в «TM» раньше, чем чистятся знаки. Итог: игра из библиотеки показывается как новая; то же для проверки RAWG (для длинных названий спасает порог 0.9, для коротких нет). Предложение: удалять `™®©℠` до `normalize('NFKD')` (так уже сделано в `hltb/normalize.ts`). Тест: `it.fails` «BUG-D2».

### D3. Негативный результат не кэшируется и не имеет паузы (низкая, backend, по контракту)
Шаги: RAWG ничего не подтвердил (или Groq вернул `error`) и открыть вкладку несколько раз/переключать режимы: каждый заход делает новый вызов Groq и списывает `LLM_DAILY_LIMIT` (проверено: 2 GET = 2 вызова). Контракт 19.4 п.4 так и требует (не залипать на пустом), но при нестабильном Groq/RAWG лимит сгорает за несколько переключений. Предложение: пауза 5-10 минут после неудачи (хотя бы в `recommend_llm_usage`/кэше «last_failed_at»).

### D4. Фильтр владения только по точному равенству (низкая, продукт)
Игры в версии «Deluxe/Ultimate/Remastered/Director's Cut» или «Hades II» против «Hades 2» в выдаче снова как новые (зафиксировано тестом). Принять или сравнивать по префиксу/без номеров.

### D5. Валидация `reason` слабая (низкая, backend)
Не вычищаются управляющие символы и bidi (`‮`, `\u0000`), кириллический «сайт.рф» проходит проверку ссылок (LINK_RE только латиница). На экране это обычный текст (XSS нет), риск косметический.

### D6. Мелочи (информационно)
- Ложные отказы матчера (игра пропадает, вреда нет): «&» против «and», «II» против «2». Римские токены только до XV, `XVII` и `XVIII` слипаются (реальных PS-игр нет).
- `coverUrl` в POST dislike: `https://` без хоста и `https://169.254.169.254/...` принимаются; сервер URL не запрашивает, SSRF нет, браузер загрузит картинку только у владельца.
- Тост-стек держит 3: четвёртый тост вытесняет первый, в том числе «Отменить» скрытия (по текущему устройству Toast; отмена остаётся через блок «Скрытые»).
- «Обновить подборку» в полёте + «Не интересно»: `run(false)` отменяет клиентский запрос refresh, сервер дозаписывает кэш и тратит refresh, а экран показывает старое `refreshLeft` до следующей загрузки. Не воспроизводил в e2e (только по коду).

## Не проверено
- Реальные Groq/RAWG (ключей нет): формат ответов и качество совпадений эмулированы; реальные названия PSN с ™/® и локализованные названия RAWG могут дать больше ложных отказов, чем в тестах.
- Реальный Neon и конкурентность на нём (BUG-D1 воспроизведён на PGlite, на Neon вероятность выше).
- Визуальная сверка карточки со скриншотом/спекой по 7 темам (проверены размеры, скролл, роли, ссылки, но не пиксели).
