## Проверено
1. Скоринг. Ручной пересчёт по 18.8: `genre_affinity` (0.6*часы/макс + 0.4*(c-d)/(c+d), среднее по жанрам, делёж 1/N в истории; playing даёт часы, но не решённые), `waiting` (365 дн = 1, насыщение, будущая дата = 0), `platinum_close` (earned/total*1.5, DLC-хвост x0.5, earned>total зажат, total 0), `dropped_genre_penalty` (ровно 50% не штрафуется, 2 из 3 да, 2 игры мало, половина жанров = -1), `duration_fit` (границы 8 и 30, промах до -1 на 20 ч), score = сумма вкладов с одним округлением. Граничные случаи: пустой бэклог, все в дизлайках, одна игра, нет часов (пометка, порядок по id), часы 0/отрицательные/NaN/Infinity, пустые жанры у кандидата и в истории, maxHours 0 (нет деления на ноль), 50 перестановок входа дают тот же результат, вход не мутируется. Значения «около N часов» склоняются верно (родительный после «около»).
2. LLM. В провайдера уходят только `id, name, genres, hours, signals`; system без данных игр; название игры с попыткой инъекции остаётся данными JSON, ответ с чужим id/ссылкой отбрасывается. Ключ: gemini в заголовке, groq в Authorization, не в URL и не в теле; сообщения ошибок только `llm_*`; в ответах API, кэше, счётчике и `console.*` ключа нет (в т.ч. когда провайдер бросает ошибку с ключом в тексте). Невалидные фразы не кэшируются, весь невалидный ответ = `error` + шаблоны. Пустой/полностью скрытый бэклог не тратит лимит.

## Баги и замечания

### N-1. Скрытые игры не вернуть после перезагрузки (средняя/низкая, backend + frontend, открытый вопрос спеки 13.1)
Шаги: нажать «Не интересно», обновить страницу. Игра исчезла, API не отдаёт список `recommend_dislikes`, снять отметку можно только тостом «Отменить» или «Вернуть скрытые» в рамках сессии. Единственный путь после перезагрузки: SQL. Если все игры бэклога скрыты, экран предлагает «новые появятся здесь сразу», но вернуть скрытые нельзя. Предложение: `GET /api/recommend/dislikes` и блок «Скрытые» (или авто-снятие дизлайка при смене статуса игры на любой иной и возврате в backlog).

### N-2. Проверка ссылок в фразе LLM по списку TLD (низкая, backend)
Шаги: `isValidPhrase('bit.ly/abc')`, `goo.gl/x`, `evil.co/a`, `evil.to`, `evil.cc` возвращают true (в `LINK_RE` TLD из короткого списка). UI показывает текст как обычный React-текст (не ссылка, XSS нет), риск косметический (в рекомендации может оказаться «кликабельный по смыслу» адрес для копирования). Предложение: отбрасывать любой токен вида `\w+\.\w{2,}\/` и вообще любые точки между буквами без пробела.

### N-3. Проверка «чужое название» слабая (низкая, backend)
Сравнивается только с названиями из той же пачки (до 3 игр) и только при длине названия >= 3; короткие названия («Ico» проходит, «Fez», «It») и игры вне пачки не ловятся. Модель получает только факты, поэтому названия вне пачки она может взять лишь из собственных знаний. Принять или добавить в стоп-лист названия всей библиотеки.

### N-4. Нет схлопывания одинаковых запросов (низкая, backend)
Два одновременных GET с пустым кэшем (две вкладки) оба тратят вызов LLM. Ограничено лимитом, поэтому лишь расход бесплатной квоты. Принять.

### N-5. Вызов LLM, закончившийся ошибкой, расходует лимит (информационно)
Так задумано в 18.8; при нестабильном провайдере 20 вызовов/сутки могут уйти на неудачи, дальше `limit` (шаблоны). Принять.

### N-6. Дизлайк вечный (низкая, продукт)
Игра, скрытая из подсказок, не возвращается даже после выхода и повторного попадания в бэклог. Связано с N-1.
