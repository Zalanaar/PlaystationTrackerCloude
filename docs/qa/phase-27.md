## Баги и замечания

| id | Серьёзность | Описание | Шаги |
|---|---|---|---|
| QA-27-1 | Средняя | Отмена «Принять» делает `PUT` прошлого статуса. Это ставит `statusChangedAt = сейчас` и перезаписывает `completed_at`/`dropped_at` датой последнего запуска (потеря ручной даты). Из-за нового `statusChangedAt` подсказка того же правила после отмены не возвращается (returned: запуск старше смены; stale: отсчёт 30 суток заново; platinum: статус «после платины»). Игра молча выпадает из подсказок, хотя отказа пользователь не давал. Тест: `status-hints-qa.test.ts` (QA-27-1). | Игра `dropped`, запуск 3 дня назад, ручной `dropped_at` стоит. Проверить: «Принять: Играю», затем Z. Закрыть и открыть очередь: подсказки нет; `dropped_at` перезаписан. Решение: серверный откат (восстановить прошлую строку `game_status`) или PUT с сохранением дат; минимум: после отмены писать/не писать отказ явно и сообщать. |
| QA-27-2 | Низкая | Кнопка «Отменить» в тосте откатывает последнее действие очереди, а не то, к которому относится тост. Если после «Принять» сделано ещё действие, нажатие на старый тост отменит новое. | Принять игру A, нажать «Не предлагать» для B, нажать «Отменить» в тосте A: откатывается B. |
| QA-27-3 | Низкая | Нет сигнала конфликта: статус сменён в другой вкладке/на другом устройстве, подсказка в очереди устарела. `PUT` проходит (последняя запись выигрывает), 404 даёт «Игра не найдена, подсказка убрана». Для продукта на 1-5 пользователей приемлемо. | Открыть очередь в двух вкладках, принять в одной, принять другое в другой: вторая перезапишет. |

### По багам
- QA-27-1: закрыт, проверено на реальном backend. Новый тест `src/server/sync/status-hints-qa-client.test.ts` берёт подсказки из настоящего `GET /api/status-hints`, строит снимок настоящими `restoreSnapshot`/`undoAcceptBody` и отправляет настоящим `putStatus` в настоящий `PUT /api/games/{id}/status` (fetch подменён только как транспорт к роуту, ответы реальные). Откат из dropped, playing (stale), backlog: статус, `statusChangedAt` и `droppedAt`/`completedAt` равны исходным до миллисекунды, подсказка того же правила возвращается. Формы тела: без прошлого статуса `{status:null, expectedStatus:'playing'}` без `restore`, строка удалена; `{status:'playing', expectedStatus:null}` при принятии; ключи `restore` ровно `status/statusChangedAt/completedAt/droppedAt`; даты ISO с `Z`; `droppedAt` только у dropped, `completedAt` только у completed (проверен и completed с датой). Расхождений мока и контракта нет.
- QA-27-3: закрыт. Реальный роут отдаёт 409 `status_conflict`, `details.status`, запись не выполняется; клиент получает `ApiError(409, 'status_conflict')` (тест выше), очередь убирает карточку, показывает warning-тост без «Отменить» с «Обновить подсказку» (e2e). Откат не затирает чужое изменение (409).
- QA-27-2: закрыт. Тост привязан к id действия (`undoAction(actionId)`), устаревший тост ничего не откатывает; Z откатывает последнее откатываемое (записи `conflict` пропускаются). Покрыто юнит-тестами `hints.test.ts` и e2e.
- QA-27-4: закрыт. У платины подпись «дата завершения — последний запуск: ДД.ММ», дата платины не показывается; без запуска подписи нет.
- QA-27-5: закрыт. Спека 13.2 использует `suggested`, `facts.statusChangedAt/platinumEarnedAt/daysSinceLaunch`, как контракт 28.4.
