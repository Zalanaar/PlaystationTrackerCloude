## Проверено по критериям
1. Фильтры/сортировка/приоритет: бакеты `<10`, `[10,30)`, `[30,60)`, `>=60`; 10, 30, 60 попадают в верхний бакет (тест `bucketOf` + SQL `>= lo and < hi` в `duration-db.test.ts`). Override приоритетнее HLTB, сброс (`hours: null`) возвращает HLTB и статус игры не меняет. found/not_found/unchecked вычисляются из `hltb_id`/`hltb_checked_at`. Сортировка `duration`: asc по умолчанию, игры без длительности в конце и в asc, и в desc. Фильтры ИЛИ внутри, И между; `counts` и `durationCounts` считаются по контракту. Скрытые игры не считаются.
2. Устойчивость HLTB: ошибка шага (и исключение) не меняет `success`, пишется `hltb_failed` (код без тела ответа); 3 ошибки подряд прерывают шаг, ошибочные игры остаются непроверенными. Пустая выдача на >=5 запросов подряд = `hltb_empty`, ничего не пишется. Потерянное совпадение у ранее найденной игры не стирает часы, только двигает `checked_at`. Пустое время при том же id сохраняет прежнее. Лимит 20, порядок backlog > playing > shelved > без статуса, пропуск completed/dropped/service/hidden/override, перепроверка 30 дней, идемпотентность повторного синка, шаг не стартует при бюджете < 3 с: всё покрыто тестами автора, я прочитал код и согласен. Парсер ответа: неожиданная форма = `bad_response`, а не «не найдено».
3. Миграция 0006: только `ADD COLUMN`, nullable, без default, 3 CHECK `> 0`. SQL для Neon: `ADD COLUMN IF NOT EXISTS`, CHECK под `pg_constraint`, запись в журнал drizzle с `WHERE NOT EXISTS`. sha256 файла миграции = хешу в SQL (66f4f500...), `when` = журналу, колонки и CHECK совпадают со `schema.ts`. Идемпотентна. Тест `release-sql-0006.test.ts` зелёный. Реальный Neon не проверялся.

Неизвестные `genres`/`duration` -> 400, `LT10` в верхнем регистре тоже 400 (ключи бакетов регистрозависимы, жанры нет: ок по контракту). ## Баги и замечания

### N-1. Две одноимённые кнопки «Сохранить» в окне игры (низкая, frontend)
Шаги: открыть игру завершённую/брошенную, нажать «Изменить» у даты завершения. В диалоге две кнопки «Сохранить» (дата и длительность) без различимого доступного имени: скринридеру непонятно, какая к чему; сломало strict-локатор e2e. Предложение: `aria-label="Сохранить дату завершения"` / `"Сохранить длительность"`.

### N-2. Защита `hltb_empty` не работает на малых партиях (низкая, backend)
Порог `HLTB_SUSPICIOUS_EMPTY = 5` подряд. Если к проверке осталось 1-4 игры (обычный режим после первой полной загрузки: новые игры в день), и HLTB «сломан» пустой выдачей, они получат `not_found` на 30 дней без предупреждения. Ручной ввод и сам статус «не найдено» это смягчают. Предложение: при малой партии не ставить `checked_at` для пустых выдач, либо перепроверять `not_found` раньше (например 7 дней).

### N-3. Округление 0.05 -> 0.1 и 1000.04 -> 1000 вместо 400 (информационная)
Контракт: «число 0.1..1000, округляется до 0.1»; границы проверяются после округления. Допустимо, но стоит дописать в §16.5.

### N-4. Нет фильтра «без жанра» (информационная, продукт)
Игры без жанров видны только без жанрового фильтра. Для бэклога это приемлемо, если таких мало; не проверено на реальных данных.
