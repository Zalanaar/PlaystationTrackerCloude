## Баги и замечания

### N-1. Две одноимённые кнопки «Сохранить» в окне игры (низкая, frontend)
Шаги: открыть игру завершённую/брошенную, нажать «Изменить» у даты завершения. В диалоге две кнопки «Сохранить» (дата и длительность) без различимого доступного имени: скринридеру непонятно, какая к чему; сломало strict-локатор e2e. Предложение: `aria-label="Сохранить дату завершения"` / `"Сохранить длительность"`.

### N-2. Защита `hltb_empty` не работает на малых партиях (низкая, backend)
Порог `HLTB_SUSPICIOUS_EMPTY = 5` подряд. Если к проверке осталось 1-4 игры (обычный режим после первой полной загрузки: новые игры в день), и HLTB «сломан» пустой выдачей, они получат `not_found` на 30 дней без предупреждения. Ручной ввод и сам статус «не найдено» это смягчают. Предложение: при малой партии не ставить `checked_at` для пустых выдач, либо перепроверять `not_found` раньше (например 7 дней).

### N-3. Округление 0.05 -> 0.1 и 1000.04 -> 1000 вместо 400 (информационная)
Контракт: «число 0.1..1000, округляется до 0.1»; границы проверяются после округления. Допустимо, но стоит дописать в §16.5.

### N-4. Нет фильтра «без жанра» (информационная, продукт)
Игры без жанров видны только без жанрового фильтра. Для бэклога это приемлемо, если таких мало; не проверено на реальных данных.

## Баги
### H-1. Перепроверка «не найдено» может зациклиться при часах клиента впереди сервера (средняя, backend/frontend)
Шаги: на устройстве, у которого время впереди серверного хотя бы на секунды (телефон), включить «Перепроверить не найденные» и запустить. Фронт шлёт `since = Date.now()` клиента (будущее для сервера). `route.ts` на КАЖДОМ вызове обрезает будущее `since` до текущего серверного «сейчас»: `recheckBefore = new Date()`, оно растёт, и игры, перепроверенные в предыдущем вызове (`hltb_checked_at = прошлое now`), снова попадают под `hltb_checked_at < recheckBefore`. `done=false` (budget, `processed>0`) каждый раз -> цикл идёт до лимита 40 вызовов (~30 минут), одни и те же not_found игры перепроверяются, слот `running` занят, синк блокируется. Тест: `qa-hltb-mass.test.ts`, `it.fails('BUG-H1 ...')` (имитирует логику route; убрать `.fails` после починки). Фикс: брать границу не из `now()` вызова, а фиксировать серверно (например фронт берёт время из заголовка `Date` первого ответа, либо сервер отдаёт `since` в ответе/принимает только прошлое и иначе 400, либо отбор по «не проверялось в этом запуске» через `hltb_checked_at < since` с запасом). Без перепроверки (по умолчанию) не проявляется.
