## Баги (по тяжести)
### Средняя
**QA-33-1. Меню «…» нижних строк «Списка» уходит под нижнюю навигацию (мобильный, все темы).** Не блокер, хотфикс не срочный.
Шаги: 360x640, `/backlog`, вид «Список», в списке 8 игр, прокрутить в конец, нажать «…» у последней строки. Видны только «Открыть игру» и «В сервис», остальные пункты под `.ps-tabbar`, страница дальше не прокручивается. Для третьей строки (нижняя на первом экране) меню тоже обрезано, но можно прокрутить страницу при открытом меню (проверено, меню не закрывается). Снимки: `backlog-menu-360-*-OVERLAP.png`, `backlog-menu-last-row-360-night-BUG.png`. Обход: открыть окно игры. Правка: переворот меню вверх у нижнего края или `padding-bottom` списка под высоту меню. Тест: `e2e/qa-phase33-menu.spec.ts` (после исправления убрать `test.fail`).

### Низкая
**QA-30-1. Битая дата в ответе RAWG (например `2020-13-45`) роняет разбор всей страницы.** `validDate` в `src/server/catalog/rawg.ts:56` вызывает `new Date(...).toISOString()`, который бросает `RangeError`; это не `CatalogError`, страница теряется, фасет считается сбойным (`network`). Затрагивает и поиск новинок Плана (17.9). Шаги: `parseDiscoverPage({ next: null, results: [{ id: 1, name: 'x', released: '2020-13-45' }] })`. Тест: `it.fails` в `qa-phase30.test.ts`. Правка: проверять дату через `Date.parse`/`Number.isNaN` или try/catch.

**QA-30-2. Совпадение с библиотекой не ловит часть вариантов названий.** «Final Fantasy VII Remake» (RAWG) не равно «FINAL FANTASY VII REMAKE INTERGRADE» (PSN), «Resident Evil 4» не равно «Resident Evil 4 Remake»; русские названия PSN («Ведьмак 3: Дикая Охота») не совпадают с английскими RAWG, выручает только `hltb_name`. Итог: купленная игра может появиться в «У тебя нет», убирается кнопкой «Не интересно». Ложных исключений (Hades/Hades II, RE2/RE4, God of War/Ragnarök, Dark Souls II/III) нет. Тесты фиксируют текущее поведение (группа «известные пробелы»). Рекомендация: добавить `intergrade` и т.п. в слова издания или учитывать подстроку с началом названия; решение за оркестратором.

**QA-31-1. Текст шага тура: «во вкладке «У тебя нет» новые игры PlayStation».** Подборка это высоко оценённые вышедшие игры (Metacritic >= 75), не новинки. Файл `src/ui/tour/steps.ts:73-74`. Правка копирайта: «игры PlayStation, которых нет в библиотеке».

**QA-31-2. Косметика карточек «У тебя нет» на десктопе.** Карточки в одном ряду разной высоты (кнопка «Не интересно» переносится на вторую строку при «Уже в Плане»), низ карточек не выровнен (`discover-desktop-*.png`). При `stale` и `partial` одновременно показывается только пометка «вчерашняя» (по одной на раз; по спеке допустимо, но partial не виден).

**QA-34-1. Расхождение контракта и кода.** Контракт 26.3 пишет «исключённые месяцы версий группы», код (`details.ts`, `loadHistoryInput`) берёт исключения только по `id` открытой игры. UI не даёт ставить исключения на дубль, поэтому практического эффекта не нашёл; либо поправить контракт, либо запрос.

## Чек-лист по критериям

### Фаза 30
- Ни одной игры библиотеки в выдаче: скрытые, дубли Фазы 23, другое написание (™, ®, апостроф, «(PS5)», «Complete/Ultimate Edition», «PS5»), `hltb_name`, активный План, «Не интересно»: ОК (dev-тесты и мои, плюс исчезновение сразу после добавления игры в библиотеку, фильтр действует при чтении). Пробелы: QA-30-2.
- Выключенный и падающий LLM (http, мусор, сеть, пауза после 3 неудач): ОК, шаблонные причины, вызов возвращается в бюджет. LLM не меняет состав игр, чужие id и названия отбрасываются.
- Лимиты: `provider_usage` считает каждый реальный запрос (сумма равна числу запросов), при `userLimit=1` второй запрос не уходит, статус `limit`; `discover_auto_calls` не больше 1 в сутки, повтор в те же сутки = `skipped`: ОК.
- Шаг синка: не больше 8 запросов за запуск (даже при `next` на каждой странице), повтор в те же сутки без запросов, ошибка шага ловится в engine (`discover_step_failed`), итог синка не меняется: ОК.
- Изоляция: два пользователя, подборка, `provider_usage`, `recommend_llm_usage` по `user_id`, ключ RAWG не в ответах и не в кэше: ОК.
- GET не вызывает сеть (fetch-шпион, параметры `?refresh=1&force=1` игнорируются): ОК. Вчерашняя подборка: `stale=true`, без сети.
- Мусор в POST/DELETE dislike: 17 вариантов тела (null, массив, не JSON, чужой источник, лишние поля, id с пробелом, `/`, 65 символов, число, пустой title, 201 символ, cover http и javascript:, без cover), чужой Origin, неверный Content-Type, id вида SQL-инъекции: все 400, в БД ничего; повтор POST одна строка; DELETE несуществующего = 200: ОК.
- Форма RAWG: фикстура реальной формы (`count/next/previous/results`, `platforms[].platform{id,name,slug}`, `genres[]`, `tags[]`, `metacritic` null, `rating` 0..5) разбирается верно; параметры запроса (`platforms=187,18`, `genres`/`tags` по slug, `metacritic=75,100`, `ordering=-metacritic`, `exclude_additions`, `page_size=40`) соответствуют документации rawg.io/apidocs. Живой ключ не использовался. Баг: QA-30-1.
- Прод-риск: колонка есть в `0012_llm_budget.sql`, схема без изменений после 0018, новой миграции не нужно: ОК.
