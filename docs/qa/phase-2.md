## Безопасность

- Логи: `console.*` только в двух местах, оба через safeErr. Токены/NPSSO не логируются. error_message: safeErr (точные секреты, Bearer, JWT, base64-подобное 32+, обрезка 500); тест мой: секреты в тексте ошибки PsnError и обычной Error не попадают ни в error_message, ни в cursor, ни в warnings. SQL-параметры вырезаются (`params:`).
- Ответы API: 503/500 без деталей (e2e: нет строки подключения в теле).
- AES-256-GCM: ключ 32 байта base64 проверяется, IV 12 байт случайный на каждую запись, tag проверяется, подмена и чужой ключ отвергаются (тесты). Формат v1. Замечание: при смене ключа токены тихо игнорируются и идёт NPSSO (по замыслу).
- psn_auth: в статус отдаётся только дата истечения.

## Классификация ошибок по тексту (риск)

Реальные тексты psn-api (проверено по dist/index.mjs): ошибки данных = `error.message` из JSON PSN или «Unexpected Error»; GraphQL-ответы бросаются как `JSON.stringify(ответ)`; обмен токенов НЕ бросает, а возвращает объект с `undefined` токенами при любом ответе (включая 429/5xx с JSON).
- Главный риск: BUG-1.
- «Unexpected Error» (нет `error.message`, например 401 с другой формой тела) = psn_unavailable: три повтора с паузой вместо принудительного refresh. Безвредно, но медленно, а отказ потом всплывёт как psn_unavailable, а не auth_expired.
- `\b429\b|\b401\b|\b403\b|\b404\b` и слова `permission|privacy|forbidden` ищутся по всему тексту, включая JSON.stringify ответа GraphQL с произвольными полями: возможны ложные срабатывания (например 404 внутри id или сообщения). Порядок проверок: rate_limited, npsso, access_denied, auth_expired. Сообщение с «user not found»/«resource not found» = access_denied даже при протухшем токене (маловероятно).
- Паттерн `access token` относит к auth_expired любое сообщение, где встречается эта фраза.
Подтвердить можно только реальными ответами PSN.

## Баги

**BUG-1 (средняя). 429/сбой PSN при обмене токенов маскируется под auth_expired.**
Шаги: в `psn_auth` есть refresh, PSN при обмене отвечает 429 или 5xx с JSON (psn-api не бросает, а возвращает объект без токенов, `src/server/psn/auth.ts` `toPair` -> null). `getAccessToken` трактует null как «refresh отвергнут», идёт на NPSSO; `/authorize` без `location` -> бросает «Is your NPSSO code valid?» -> null -> `auth_expired`. Итог: запуск `failed/auth_expired` без повторов, на сайте баннер «нужен новый NPSSO», хотя NPSSO в порядке; следующий синк через сутки. Тест: `src/server/sync/qa-phase2.test.ts` (it.fails «БАГ: 429 при обмене токенов...»). Решение: в `defaultAuthApi` смотреть HTTP-статус/поле `error` ответа (вызывать токен-эндпоинт самим или проверять `error`/`error_description`): `invalid_grant`/`invalid_request` = отказ, 429/5xx/иное = транзиент PsnError с повторами; а на `/authorize` различать 302 без code (NPSSO плох) и 429/5xx. После исправления снять `it.fails`.

**BUG-2 (низкая). Самовызов берёт origin из `req.url`** (`src/server/sync/service.ts` `continueChain`). Для `POST /api/sync` (Origin не обязателен) подмена Host/X-Forwarded-Host направила бы `Authorization: Bearer CRON_SECRET` на чужой хост. Эксплуатируется только владельцем сессии, на Vercel Host маршрутизируется платформой. Решение: брать origin из доверенной переменной (`VERCEL_URL`/`APP_URL`) или не слать секрет, если host не совпадает с ожидаемым.

**BUG-3 (низкая). Предохранитель 20 работает только у отправителя.** `?continue=<id>` (с Bearer) возобновляет partial/timeout запуск независимо от `hops`. Практически не страшно (нужен Bearer), но контракт 8.2 п.3 описывает как свойство запуска. Юнит-теста самого `continueChain` и `launchSync` нет.

**BUG-4 (низкая, исправлено в e2e). Устаревший e2e** `закрытый сайт > cron: без Bearer и с чужим` ждал 200 от заглушки Фазы 1 (падал 2 раза). Правка: ожидается 503 db_unavailable (Bearer пройден, БД e2e недоступна). Детерминированность: в `e2e/env.ts` добавлены фиктивные `PSN_TARGET_ONLINE_ID`, `TOKEN_ENCRYPTION_KEY`, пустой `PSN_NPSSO`, иначе результат зависел от локального `.env` (500 config_error или 503).

**Замечание (не баг).** `SYNC_TIME_BUDGET_MS` допускает до 280000 при `maxDuration = 60`: неверное значение в env превысит лимит функции. Стоит ограничить сверху ~55000.
