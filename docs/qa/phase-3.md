## Как устроены e2e

БД в e2e недоступна, поэтому в `e2e/collection.spec.ts` ответы `/api/*` эмулируются внутри теста (`e2e/collection-mock.ts`, 10 игр, состояние в памяти: фильтры, год по МСК, счётчики, правила дат, сбои и задержки по запросу). Эмуляция написана по контракту §9, а не по коду. Реальные фильтры SQL, год по МСК, bulk-откат покрыты vitest на PGlite (`query.test.ts`). `e2e/collection-api.spec.ts` бьёт в реальные роуты dev-сервера (валидация и права отвечают до БД). Ограничение: связку UI с реальной БД на Neon e2e не проверяют.

Совпадает: шапка статистики (аватар, 4 плитки, активная «Игр»), блок «Играю сейчас», ряд «Продолжить», сетка с чипами времени/запусков, бейдж PS, нижняя полоса трофеев, плашка «Завершено/Брошено · дата», таблица списка, чипы статусов с иконками, подсветка активной карточки. Темы применяются на одной разметке; Memory Card, Crystal Towers, Wave, Tiles, Activity, Dark визуально различаются, как в `themes-overview.png`.

Критичных расхождений нет. Замечания:
- (косметика, известное) нет hover-попапа §4.4.
- (косметика, известное) нативные `<select>` для года и сортировки: стилизованы, но выпадающий список системный, в темах не окрашивается.
- (косметика, известное) имя «Артём» зашито; в референсе «Артём Евтеев». Мелочь, но при смене владельца правка в коде.
- (по решению продукта) в референсе фильтры платформ (PlayStation/Xbox/Switch/PC) и вкладки «План/Подскажи»: вне MVP, не реализованы, корректно.
- (косметика) в референсе кнопка «Импорт из PSN», у нас «Синк сейчас»; поиск без «добавить новую» (вне MVP).
- (косметика) без обложек (в e2e нет картинок) плейсхолдер с названием выглядит ровно; с реальными обложками сверить глазами при приёмке на реальных данных.
- (мобильный) на полностраничном скриншоте tab bar перекрывает ряд «Продолжить»: артефакт fixed-панели при fullPage; при обычной прокрутке нижний отступ контента нужно проверить на устройстве (не подтверждено).

## Риски и замечания без воспроизведения тестом

- R1 (ИСПРАВЛЕНО: `setFilters` берёт последнее запрошенное состояние (ref)) (низкая) `setFilters` строится из `filters` текущего рендера: два изменения фильтров в пределах одного кадра (например, коммит debounce поиска одновременно с кликом по табу) могут потерять первое. В обычном использовании не воспроизводится.
- R2 (ИСПРАВЛЕНО: `loadMore` защищён reqId и AbortController) (низкая) «Показать ещё» не использует `reqId`: если фильтры сменились во время подгрузки, строки старого набора могут добавиться в новый список. Нужен guard по `filtersKey`.
- R3 (ИСПРАВЛЕНО: выбор сбрасывается при смене фильтров (тест в e2e)) (низкая) Режим выбора: выбор сохраняется при смене фильтров, невидимые игры остаются в `selected` и попадут в массовую смену; «Выбрать все» берёт только загруженные.
- R4 (низкая) Массовая смена >250 id шлётся несколькими запросами: между пачками атомарности нет (на практике нужна загрузка 250+ карточек).
- R5 (низкая) Оптимистичный `applyStatusLocally` для completed без `lastPlayedAt` берёт клиентское now, сервер возьмёт своё: в пределах ответа выравнивается.
- R6 (инфо) Откат оптимистичных обновлений (replaceGames/shiftCounts) при сбое проверен e2e для одиночной и массовой смены; конкурентные смены двух разных игр одновременно не тестировались.
- R7 (a11y, косметика) табы статусов реализованы как группа кнопок с `aria-pressed`, а не `tablist`: допустимо, скринридер читает «нажато». Диалог: `role=dialog`, `aria-modal`, `aria-labelledby`, фокус-ловушка и возврат фокуса проверены, фон не `inert`.
- Не проверялось: реальная БД Neon через UI, реальные обложки, Safari/iOS.
