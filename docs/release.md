# Релиз и эксплуатация

Основа: `docs/api-contract.md` §5 (переменные), §6 (миграции), `docs/api-notes.md` (NPSSO).

## 1. Порядок релиза Фаз 5–6 и правок (service, оценка часов)

Код в `main` ссылается на статус `service`. Без миграции `0001` в базе запрос сводки коллекции падает («invalid input value for enum game_status_value»). Поэтому порядок строгий: **миграция, потом деплой**.

1. **Backup.** В Neon сделать ветку (branch) от прода: миграция трогает enum `game_status_value`, которым пользуется `game_status` (ручные статусы, невосстановимые, `api-contract.md` §6.7).
2. **Миграция.** Локально или из CI с `DATABASE_URL_UNPOOLED` прода: `npm run db:migrate`. Применится `0001_game_status_service.sql` (`ALTER TYPE ... ADD VALUE 'service'`). Данные не теряются; откатить нельзя (значение enum остаётся неиспользованным).
3. **Деплой.** Мёрдж PR в `main` (Vercel собирает prod). Дождаться зелёного деплоя.
4. **Проверка после деплоя** (под паролем):
   - `/` открывается, блоки на месте, блок «Игры-сервисы» скрыт, пока нет игр с этим статусом.
   - Сменить статус одной игры на «Сервис» и вернуть: блок появляется и пропадает.
   - `/stats`: выбор года, часы по месяцам, легенда «Измерено / Оценка», плашка.
   - `/wrapped`: выбор года, «Смотреть итоги», слайды листаются.
   - `/api/health`: последний синк и статус.
5. **Откат кода:** Vercel → Deployments → предыдущий деплой → Promote. Миграция откатывать не нужно: старый код её не замечает.

## 2. Cron

- Расписание в `vercel.json`: `0 20 * * *` UTC (23:00 МСК). На Hobby точность в пределах часа.
- Cron защищён `CRON_SECRET` (Vercel подставляет сам при заданной переменной).
- **Не проверялся на Vercel** (проверен только локально через Bearer). Проверка после первого релиза:
  1. Vercel → Project → Settings → Cron Jobs: задание `/api/cron/sync` есть.
  2. На следующее утро: `/api/health` или панель синка показывает запуск `daily` со статусом `success` и датой вчерашнего вечера.
  3. В `sync_runs` появилась строка `kind = daily`; в `playtime_snapshots` новые строки за дату.
- Если за сутки запуска нет: нажать «Синк сейчас» и открыть Vercel → Logs по `/api/cron/sync`.
- Пока cron не подтверждён, снимки часов копятся только от ручных синков. От снимков зависит измеренная часть часов.

## 3. Обновление NPSSO (технический аккаунт)

Когда нужно: баннер «PSN недоступен: нужен новый NPSSO» в панели синка, ошибка `auth_expired` или `npsso_invalid` в `sync_runs`. Refresh token живёт ~10 дней, при суточном синке обновляется сам; NPSSO нужен, когда refresh протух (синк не работал больше ~10 дней) или NPSSO отвергнут.

1. Войти в технический аккаунт PlayStation в браузере.
2. Открыть `https://ca.account.sony.com/api/v1/ssocookie`, скопировать значение `npsso` (64 символа).
3. Vercel → Project → Settings → Environment Variables → `PSN_NPSSO` (Production) → заменить значение. Это смена секрета: делается владельцем.
4. Redeploy последнего деплоя (переменные подхватываются при новом деплое).
5. Нажать «Синк сейчас». Баннер должен исчезнуть, в `sync_runs` статус `success`.
6. Никогда не вставлять NPSSO в чаты, логи и коммиты.

Срок жизни самого NPSSO не измерен (по документации около 2 месяцев). Поставить себе напоминание проверять баннер раз в 1–2 недели.

## 4. Мониторинг (вручную, без платных сервисов)

- Панель синка: дата последнего успешного синка и ошибка.
- `/api/health` для разовой проверки.
- Если последний успешный синк старше 3 суток: проверить cron и NPSSO.

## 5. Известные ограничения на момент релиза

- Часы до первого синка (27.10.2026) оценочные: равномерно по месяцам между первым и последним запуском. Для игр-сервисов оценка особенно грубая.
- Скорость `/api/stats` и `/api/wrapped` на реальной Neon не замерена (читают все снимки года; ~214 игр).
- Не проверены: реальные обложки на слайдах Итогов (размытый фон), iOS Safari и физический тач, контраст темы Activity на слайдах.
- Аватара в данных нет, на слайде «Старт» показан инициал.
- Отложено из Фазы 3 и редизайна: hover-попап карточки, цвет акцента из обложки (`--tint`, нужна миграция).
